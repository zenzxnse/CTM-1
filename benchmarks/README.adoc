= Benchmark methodology

Status:: Specified measurement procedure
Date:: 2026-09-11

The benchmark measures the actual service boundary after a release build. It does
not fabricate results and does not infer performance from a dry run. The service is
started on an isolated loopback port with `examples/machines/assembly-line.json`.

The script posts one validated external telemetry batch, waits for readiness, then
records cold interpretation, repeated warm interpretation, reconciliation, bounded
concurrent telemetry reads, resident memory when available, execution metadata and
the `/metrics` response. It preserves the raw JSON output byte-for-byte.

The ingestion batch follows `context-hmi-telemetry/1`: it includes the active
`model_id`, `model_revision`, `context_generation`, `source_id` and unsigned
`sequence`. Each value includes only `value`, `quality` and unsigned `timestamp_ms`;
the model declares the value type. This is the production ingestion shape, not a
separate benchmark envelope.

[source,shell]
----
python3 benchmarks/live.py --build-dir build/linux-release \
  --samples 40 --concurrency 12 --save build/benchmarks/live.json
python3 benchmarks/run.py --binary build/linux-release/context-hmi-benchmark \
  --save build/benchmarks/native.json
python3 benchmarks/plot.py --live build/benchmarks/live.json \
  --native build/benchmarks/native.json \
  --output build/benchmarks/context-hmi.svg
----

Install the optional pinned visualization dependency with
`python3 -m pip install -e '.[benchmark]'`. The service and its containers do not
depend on Python or matplotlib.

== Measurement contract

Each report records date, operating system, architecture, Python version, build
directory, model identity and revision, provider, sample count and concurrency.
Measured fields include cold and warm interpretation latency, reconciliation time,
telemetry request latency, concurrent failure count and wall time, memory when the
host exposes it, cache state and provider usage when returned. Results are local
observations, not real-time guarantees or cross-machine comparisons.

Interpretation accuracy needs a separately versioned held-out request set. A passing
HTTP request is not evidence that the selected asset was correct. Record wrong valid
asset selections, clarification quality, missing context and binding failures as
counts, with the request set kept private when it contains plant information.

Cross-platform and container reports must retain their platform identity. A Linux
cross-build, Docker Desktop run or CMake configuration does not prove native Windows,
Windows Server, Linux Mint, TCL display or vendor-runtime compatibility.
