= Context HMI local API

Status:: Accepted active contract
Date:: 2026-09-11

The native service listens on `127.0.0.1:8080` by default. Routes use the
`/api/v1` prefix and JSON. The service accepts reviewed machine context and
external current telemetry. It does not expose physical controller commands.

== Runtime identity

Each process publishes a `session_id`, active `model_id`, model revision and
`context_generation`. A model replacement increments the generation and causes
saved views and caches to be revalidated. Canonical views remain bounded and
server-authoritative. Session and view records are process-local.

== Read routes

`GET /api/v1/health` reports service, provider, model and telemetry state. It does
not claim that a provider is ready merely because the service is alive.
`GET /api/v1/session` returns the bounded local session identity and server-issued
capabilities. It is not production authentication.
`GET /api/v1/ready` reports readiness for the active model and current telemetry.
`GET /api/v1/model` returns the validated model with runtime identity fields.
`GET /api/v1/catalog` returns the reviewed screen component catalog and supported
client declarations. `GET /api/v1/scenarios` returns the available reviewed model
configurations. `GET /api/v1/metrics` reports cache, queue, provider and telemetry
counters. `GET /api/v1/audit` and `GET /api/v1/records` return bounded operational
and journal evidence when configured.

`GET /api/v1/telemetry` returns current values, quality, source timestamps,
receive age and alarms. `GET /api/v1/events` streams bounded current snapshots as
`text/event-stream`; it is not a durable event log.

== Telemetry ingestion

`POST /api/v1/telemetry` accepts a bounded current batch. The batch must identify
the active model and revision and contain only declared tag IDs. Values must match
declared data types. Each value preserves quality and an unsigned source timestamp in
milliseconds. The batch sequence is carried at the top level. The whole batch is
validated before it replaces the current snapshot. Missing values are unknown and
values older than the configured freshness
window are stale. The route does not store a historian.

[source,json]
----
{
  "schema_version": "context-hmi-telemetry/1",
  "model_id": "assembly-line-a",
  "model_revision": 1,
  "context_generation": 0,
  "source_id": "line-gateway",
  "sequence": 42,
  "values": {
    "line-a.throughput": {"value":42.5,
      "quality":"good", "timestamp_ms":1789084800000}
  }
}
----

== Interpretation and views

`POST /api/v1/context/retrieve` accepts a prompt and returns bounded candidates
and context sizing without calling a provider. `POST /api/v1/interpret` accepts a
prompt and optional `interpreter` of `rules`,
`llama` or an explicitly configured OpenAI-compatible provider.

[source,json]
----
{"prompt":"Show the status of the packaging line","interpreter":"rules"}
----

The server retrieves bounded context before provider inference. A ready response
contains a validated task and canonical view. A clarification response contains a
message and candidates and creates no view. A provider cannot select a tag address,
invent an asset, or grant a permission. `execution` metadata includes candidate
scope, context bytes, estimated tokens, truncation, retrieval and interpretation
cache states, provider usage when returned, stage timings and validation evidence.

`POST /api/v1/resolve` accepts a validated task and returns a server-owned view.
`POST /api/v1/reconcile` accepts a cached `view_id` or exact cached view and
revalidates it against the current model. Removed or semantically changed bindings
become explicit issues; they are never silently rebound.
`POST /api/v1/scenario` selects a reviewed model configuration and increments the
context generation. Existing views and caches are then revalidated or invalidated.

== Errors and limits

Errors use `{ "error": { "code": "...", "message": "..." } }` and never include
stack traces, credentials or source secrets. Request bodies, JSON depth, model size,
prompt length, telemetry values, event clients, provider concurrency and cache sizes
are bounded by configuration and native validation.

Relevant status mappings are:

* `400` for malformed JSON or invalid content;
* `403` for an unsupported origin or policy;
* `404` for an unknown route, model or view;
* `409` for stale model generation or reconciliation conflict;
* `413` for an oversized body;
* `415` for a missing JSON content type on mutation;
* `422` for model, task, binding or telemetry validation;
* `429` for bounded concurrency or queue saturation;
* `502` for an explicitly configured provider failure.

The default bind is loopback. `--allow-remote` changes binding only and does not
provide production authentication. Remote provider use is opt-in, TLS-gated and
requires a key from an environment variable. The browser receives no key.
