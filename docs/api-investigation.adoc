= Provider and vendor API investigation

Date:: 2026-09-11
Status:: Research note, not runtime evidence

== llama.cpp

The official https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md[llama.cpp server documentation]
describes the OpenAI-compatible `/v1/chat/completions` endpoint, structured JSON
responses, prompt caching, cache reuse and metrics. The local provider uses that
boundary with a finite task schema. It must continue validating every response in
native code because endpoint compatibility and interpretation quality depend on the
server build, model and chat template. No weights are committed.

The request layout places stable instructions, tools and schema before bounded
retrieved context and the operator request. This allows exact-prefix cache reuse.
The service reports provider usage and cache fields only when the provider returns
them. See link:context-efficiency.adoc[context efficiency].

== OpenAI-compatible remote providers

The optional remote boundary is disabled by default. A configured endpoint must use
TLS, receive only approved bounded context, and read its key from an environment
variable. Groq's https://console.groq.com/docs/prompt-caching[prompt caching guidance]
describes exact-prefix caching for supported models and the static-before-dynamic
request layout. A remote run requires separate privacy approval and records endpoint
provider, model, build, region policy and usage metadata.

== EcoStruxure Operator Terminal Expert

Schneider's official https://www.se.com/us/en/product-range/62621-ecostruxure-operator-terminal-expert/[product page]
describes customizable HMI screen design, project exploration, data access and
remote monitoring capabilities. The official
https://download.schneider-electric.com/files?p_Doc_Ref=DIA5ED2140703EN[product catalogue]
describes the engineering product and supported terminal families.

Those public materials do not establish a public C++ runtime API, native screen
generation SDK or an endpoint this service can execute against. The active service
therefore exposes a vendor-neutral JSON model and screen contract. Any future
EcoStruxure adapter must name the exact installed product and version, preserve
source provenance, use a reviewed read-only import or broker boundary, and be
tested on that installation. No compatibility claim is made from documentation
alone.

== AVEVA and Ignition

The supplied AVEVA Operations Control and Ignition materials describe HMI, MES and
AI integration concepts. They do not provide an installed endpoint, licensed SDK or
test artifact in this workspace. They remain documented mapping profiles only. A
future adapter must prove identity, ownership, units, relationships, permissions,
freshness and failure behavior without manufacturing metadata from display paths or
names.

== Evidence boundary

All findings above are documentation research. They do not prove a live model,
provider, controller, HMI runtime or vendor product. See
link:evidence-conventions.adoc[evidence conventions].
