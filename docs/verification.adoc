= Prototype verification

Date:: 2026-09-10

This record covers the first local PS2 prototype. It distinguishes native behavior,
provider-contract tests, build checks and work that still needs target equipment.

Node.js 24.19.0; npm 11.9.0; clang-format 23.1.0; Ruff 0.16.6; Pyright 1.1.414.

== Reproduce the main checks

Run from the project root with the prerequisites listed in the README:

[source,shell]
----
npm --prefix workbench ci
npm --prefix workbench run check
npm --prefix workbench run format:check
npm --prefix workbench run build
cmake --preset release
cmake --build --preset release --parallel 2
ctest --preset release
python3 -m ruff check tests tools benchmarks
python3 -m compileall -q tests tools benchmarks
npm exec --yes --package=pyright -- pyright
clang-format --dry-run --Werror src/context_hmi/*.cpp src/context_hmi/*.hpp tests/*.cpp tools/*.cpp
cmake --install build/release --prefix ./build/installed
----

The Python integration suites launch temporary loopback services. A missing native
executable fails verification; these suites do not silently skip unavailable binaries.
The two native test executables use explicit checks that remain active in Release builds.

== Sanitizer limitation

The first sanitizer run could not complete LeakSanitizer's process inspection in this
managed workspace. It reported a ptrace/proc access failure. The following run retained
address and undefined-behavior checks and passed all four suites:

[source,shell]
----
cmake --preset sanitizers
cmake --build --preset sanitizers --parallel 2
ASAN_OPTIONS=detect_leaks=0 ctest --preset sanitizers
----

This is not evidence of leak freedom. Leave leak detection enabled when running on a
host that supports it. The project preset does not globally disable leak detection.

== Limits of this evidence

* No live llama.cpp binary or model was run. The wire format was checked against official
  source; the native client's response and failure handling were tested with mock responses.
* No OPC UA server, physical PLC, Schneider editor/runtime or LVGL client was exercised.
* Windows and compact-panel compatibility remain unverified.
* Browser interaction, visual layout, animation and optional browser tool registration
  have not been exercised in a browser. Build and static HTTP checks are not browser QA.
* Test fixtures are authored examples. They do not establish interpretation accuracy on
  unfamiliar requests, plant data, or configuration edits held out from development.
* No full request-to-paint latency, process memory, throughput or engineering-effort
  comparison is claimed. The native benchmark has a separate, narrow measurement contract.
